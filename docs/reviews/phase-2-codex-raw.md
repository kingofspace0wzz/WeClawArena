1. **Recoverability — BUG.** [`recoverability.py`](/home/kingofspace0wzz/llm/mas-clawsocialarena/clawsocialarena/clawsocialarena/saf/scorers/recoverability.py:11) only compares `(agent_id, action_id)` sets. That detects deletions, but it completely misses payload/phase/integrity tampering under the same IDs, and it gives `1.0` for primary-only injected actions because extra primary rows are ignored. I reproduced both: same key with tampered payload scores `1.0`, and one extra primary action also scores `1.0`. That is weaker than the spec’s “divergence signals a gap” language.

2. **Policy Checkability — BUG.** [`policy_checkability.py`](/home/kingofspace0wzz/llm/mas-clawsocialarena/clawsocialarena/clawsocialarena/saf/scorers/policy_checkability.py:12) handles missing shape safely enough: nested dict traversal works, bad shapes return `False`, terminal `None` counts as present if the path ends there. The real problem is semantic. Spec §3.2 says decidable iff required fields are present in the record and SEM at the relevant moment is well-formed; this implementation ignores SEM entirely and allows required fields to be assembled across different records. I reproduced `{"payload.content","payload.recipient_id"}` scoring decidable from two different records. Also, `gt.policies` is never loaded into the registry, so this dimension can silently default to `1.0`.

3. **Attribution DAG — BUG.** [`attribution_dag.py`](/home/kingofspace0wzz/llm/mas-clawsocialarena/clawsocialarena/clawsocialarena/saf/scorers/attribution_dag.py:22) reduces everything to edge triples `(src,dst,label)`. Spec §3.2 explicitly cares about node labels and says F1 is averaged over chains of length `>= 2`; this implementation ignores chain decomposition, depth, and node labeling. Worse, [`eval/runner.py`](/home/kingofspace0wzz/llm/mas-clawsocialarena/clawsocialarena/clawsocialarena/eval/runner.py:58) hardcodes `produced_dag={"nodes":[],"edges":[]}`. So for any non-empty GT DAG, Phase 2 eval will score attribution as `0.0` regardless of the run.

4. **Evidence Integrity — CONCERN.** The implementation matches the written formula in spec §3.2: `Σ w_i * 1[level_i >= required_i] / N` ([`evidence_integrity.py`](/home/kingofspace0wzz/llm/mas-clawsocialarena/clawsocialarena/clawsocialarena/saf/scorers/evidence_integrity.py:24)). Records exceeding the requirement do raise the score relative to merely meeting it; that is by design of this formula, not an accidental inflation bug. But this creates a nasty mismatch: if the requirement is `HASH_CHAINED`, perfect compliance only scores `0.75`, below the declared `0.80` pass threshold. The MVP fixture change from `"outbound_message": 3` to `{}` in [`scenario.gt.json`](/home/kingofspace0wzz/llm/mas-clawsocialarena/clawsocialarena/fixtures/scenarios/cu_scheduling_mvp/scenario.gt.json:10) is papering over that mismatch, not proving the pipeline is correct. It also hides the fact that `AuditedMessageBus` only ever stamps `HASH_CHAINED` ([`audited.py`](/home/kingofspace0wzz/llm/mas-clawsocialarena/clawsocialarena/clawsocialarena/bus/audited.py:53)).

5. **Phase-Scoped Policy — BUG.** [`phase_scoped_policy.py`](/home/kingofspace0wzz/llm/mas-clawsocialarena/clawsocialarena/clawsocialarena/saf/scorers/phase_scoped_policy.py:35) is not implementing “decidable AND satisfied” correctly. If there are zero records in the declared phase, the policy still counts as satisfied because `decidable_and_satisfied` starts `True` and never flips; I reproduced a `1.0` score for a `REPAIR` policy with only `DISCOVERY` records. It also treats any in-phase record missing a required field as a hard policy failure instead of “not decidable”, and it does not report the spec’s required sub-components separately.

6. **SAFScorer geometric mean — OK.** [`saf_scorer.py`](/home/kingofspace0wzz/llm/mas-clawsocialarena/clawsocialarena/clawsocialarena/saf/saf_scorer.py:87) is numerically fine for `1e-10`-scale positives; I checked it in the venv and got stable results. Zero short-circuit is correct. Small caveat: weights are not normalized or validated, so custom weights can skew semantics.

7. **EvalRunner purity/reproducibility — CONCERN.** It is deterministic for fixed DB contents plus a fixed `PolicyRegistry`, but it is not a pure function of its stated `evaluate(...)` inputs. The registry is hidden constructor state ([`runner.py`](/home/kingofspace0wzz/llm/mas-clawsocialarena/clawsocialarena/clawsocialarena/eval/runner.py:31)), and `gt.policies` is ignored, so the same logs+GT can yield different scorecards depending on external setup. Diagnostics also verify only the primary log chain for all agents ([`runner.py`](/home/kingofspace0wzz/llm/mas-clawsocialarena/clawsocialarena/clawsocialarena/eval/runner.py:45)); shadow-chain tampering is not checked.

8. **MVP fixture change — BUG.** Yes, it is hiding a real issue. Not specifically “needs CROSS_AGENT_SIGNED”; the immediate mismatch is that a `HASH_CHAINED` requirement yields `0.75`, not `1.0`. Emptying `integrity_requirements` makes the MVP pass by exempting the metric.
